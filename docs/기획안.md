# 계약지킴이 - 소상공인 임대차 계약 AI 분석 서비스

📅 작성일: 2026년 4월 1일  
👥 팀 구성: 미정  

---

## 1. 프로젝트 개요

계약지킴이는 소상공인이 임대차 계약서(PDF/이미지)를 업로드하면,  
**OCR → 구조화 → RAG 기반 법령 대조 → 독소 조항 리포트**를 자동 생성하는 AI 서비스입니다.

### 개발 배경

어머니가 식당을 4년째 운영 중이며, 건물주와의 임대차 계약 만료를 앞두고  
계약서 검토를 변호사에게 맡기기 부담스러워 그냥 서명하려 하셨습니다.  
이 경험을 출발점으로 실제 수요가 있는 서비스를 직접 만들고자 합니다.

### 기술 목표

- FastAPI 기반 AI 파이프라인 (OCR → RAG → LLM) 설계 및 구현
- Spring Boot에서 `AIServiceClient` 인터페이스 추상화 + Resilience4j Circuit Breaker로 AI 장애 대응 설계
- 실제 배포 경험 (AWS + CI/CD + Docker)
- 실사용자(어머니) 테스트를 통한 UX 개선 과정 기록

## 2. 시장 분석

### TAM (전체 시장)
- 국내 임대차 계약 체결 건수: 연간 약 200만 건 (상가 + 주거)
- 상가 임차인: 약 100만 건/년

### SAM (유효 시장)
- 계약 갱신 시점의 소상공인 중 디지털 서비스 사용 가능자
- 약 30만 명/년 (스마트폰 보유 + 앱 사용 가능)

### SOM (실제 목표 시장, 1~2년)
- 초기 타겟: 서울/수도권 자영업자 중 SNS·카카오 채널 유입
- 목표 MAU: 3,000명 (1년차)
- 목표 유료 전환: 500명 (월 9,900원 플랜)

### 경쟁 분석

| 서비스 | 특징 | 한계 |
|---|---|---|
| 로톡 | 변호사 매칭 | 비용 높음, 즉각 분석 없음 |
| 네이버 지식iN | 무료 답변 | 개인화 없음, 신뢰도 불균일 |
| 일반 법률 챗봇 | 일반 질의응답 | 계약서 직접 분석 불가 |
| **계약지킴이** | **계약서 업로드 → 즉시 분석** | 개발 중 |

## 3. 전체 시스템 아키텍처

### 3-1. 역할 분담 설계

두 프레임워크를 분리한 이유는 도메인 특성의 차이와 포트폴리오 목표입니다.

| | Spring Boot | FastAPI |
|---|---|---|
| **주요 역할** | 인증/인가, 계약 이력 CRUD, 알림, AI 서비스 통합 | OCR 파이프라인, 벡터 검색, LLM 호출, 문서 전처리 |
| **선택 이유** | AI 장애 격리 설계 (`AIServiceClient` 추상화 + Circuit Breaker + fallback), 비동기 분석 요청 처리 | Python ML 생태계 활용, 비동기 AI 추론에 유리 |
| **DB 접근** | PostgreSQL (JPA) | pgvector (벡터 통합) |
| **통신** | REST API (외부 클라이언트), WebClient로 FastAPI 비동기 호출 | 내부 REST API (Spring Boot → FastAPI) |

**Spring Boot에서 AI 통합 설계 포인트**

- `AIServiceClient` 인터페이스로 AI 서비스 추상화 → 구현체 교체 가능 (`FastAPIAIServiceClient`, `CachedAIServiceClient`, `MockAIServiceClient`)
- Resilience4j Circuit Breaker + TimeLimiter: FastAPI 또는 LLM API 장애 시 자동 차단 및 fallback 응답 반환
- 비동기 패턴: 분석 요청은 `202 Accepted` + job_id 즉시 반환, 클라이언트 polling으로 완료 확인

### 3-2. 요청 흐름

```
① 사용자가 계약서 PDF 업로드
② Spring Boot: 인증 확인 → S3 저장 → FastAPI로 분석 요청 (비동기)
   → 202 Accepted + job_id 즉시 반환
③ FastAPI: OCR → 조항 파싱 → Hybrid RAG → LLM 분석
④ 분석 완료 → Spring Boot DB 저장
⑤ 클라이언트 polling: GET /contracts/{id}/analysis → 완료 시 리포트 반환
```

AI 분석은 수십 초가 소요되므로 동기 호출 대신 202 + polling 패턴을 사용합니다.  
FastAPI가 다운되거나 LLM API 응답이 없을 경우 Circuit Breaker가 요청을 차단하고  
fallback 응답("분석 서비스 일시 중단, 잠시 후 재시도")을 반환합니다.

## 4. 핵심 기술 상세

### 4-1. OCR 전처리 파이프라인

| 단계 | 기술 | 처리 내용 |
|---|---|---|
| 1단계 (MVP) | pdfplumber | 텍스트 레이어 있는 PDF 직접 파싱 (OCR 불필요) |
| 2단계 | Clova OCR | 기울기/밝기 이슈 없는 환경에서 정확도 검증 |
| 3단계 | Clova OCR + OpenCV | 핸드폰 촬영 이미지 대응 (기울기 보정, 밝기 정규화 전처리 추가) |

### 4-2. 조항 단위 계약서 구조화

단순 텍스트 매칭이 아닌, 계약서의 각 조(Article)를 객체로 파싱하여 구조적으로 법령과 대조합니다.

```json
{
  "article_id": "제3조",
  "title": "임대료",
  "content": "임대료는 월 300만 원으로 하며...",
  "risk_flag": null,
  "legal_ref": "상가건물 임대차보호법 제11조"
}
```

### 4-3. Hybrid RAG 파이프라인

키워드 검색과 의미 검색을 결합하여 법령 조항 번호(예: 제11조)와 판례 의미 모두를 커버합니다.

| 검색 방식 | 용도 | 도구 |
|---|---|---|
| BM25 (Sparse) | 법령 조항 번호, 조문 키워드 정확 매칭 | rank-bm25 |
| Vector Search (Dense) | 판례·사례의 의미 기반 검색 | pgvector + Gemini embedding-001 |
| 결과 통합 | 두 검색 결과 RRF로 병합 후 LLM 컨텍스트 전달 | 직접 구현 (RRF 알고리즘) |

### 4-4. LLM 분석 및 Hallucination 방지

법률 분석 서비스 특성상 LLM이 존재하지 않는 조항 번호나 판례를 생성하면  
사용자가 잘못된 정보를 신뢰할 위험이 있습니다.

**방어 전략**
- LLM 응답에 포함된 법령 조항 번호를 지식베이스와 교차 검증
- RAG에서 관련 법령을 찾지 못하면 LLM에 "판단 불가"로 응답하도록 프롬프트 지시
- 응답에 "AI 분석 결과이며 법률 자문이 아닙니다" 면책 문구 포함

### 4-5. 지식베이스 구성

- 상가건물 임대차보호법 전문 (국가법령정보센터 API — 공공데이터, 36개 조문)
- 민법 임대차 관련 조항
- 어머니 실제 계약서 (비식별화 처리 후 테스트셋으로 활용)

## 5. 기술 스택

| 영역 | 선택 기술 | 선택 이유 |
|---|---|---|
| AI 서버 | FastAPI + Python | Python 기반이라 pgvector, Gemini SDK 등 AI 라이브러리 연동이 자연스럽고 비동기 추론에 유리 |
| 백엔드 | Spring Boot | 인증·이력 관리·알림 등 트랜잭션 처리 + `AIServiceClient` 추상화로 AI 통합 설계 포인트 |
| AI 통합 | Resilience4j | Circuit Breaker + TimeLimiter로 AI 서비스 장애 격리 및 fallback 처리 |
| LLM | GPT-4o API | 한국어 법률 문서 이해도 높음. 추후 오픈소스 모델 교체 가능성 열어둠 |
| 벡터 DB | PostgreSQL + pgvector | 별도 벡터 DB 없이 PostgreSQL 익스텐션으로 통합, 운영 복잡도 최소화 |
| OCR | Naver Clova OCR | 한국어 인식률이 핵심. EasyOCR 대비 정확도 높고 Free 플랜으로 초기 비용 없이 시작 가능 |
| RDB | PostgreSQL | pgvector 지원으로 관계형 데이터와 벡터 데이터를 하나의 DB로 통합 관리 |
| 캐시 | Redis | Phase 1 이후 도입. 동일 계약서 반복 분석 시 LLM API 비용 절감 |
| 파일 저장 | AWS S3 | 높은 내구성과 확장성, IAM으로 계약서 같은 민감 문서 안전하게 관리 |
| 알림 | FCM (Phase 3) | 계약 만료 알림 푸시 |
| 인프라 | AWS EC2 + Docker (Phase 3) | 미정 |
| CI/CD | GitHub Actions (Phase 3) | 미정 |
